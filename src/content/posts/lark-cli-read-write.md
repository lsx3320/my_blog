飞书把 CLI 开源了，仓库在 larksuite/cli，MIT。

我本机装的是 1.0.99，早就登录过，所以没走安装流程，直接打开云文档首页看它能碰到什么。

![飞书云文档主页](/posts/larkcli/07-云文档主页.png)

首页上"AI 董事会台账""阿飞稿件台账""工作周报"都在。以前要让 agent 处理这些文件，得先复制链接、配权限，或者自己下载再传。现在它能自己找。

我挑了「AI 董事会台账」打开：

![飞书多维表格](/posts/larkcli/05-多维表格.png)

五张表：议题、子任务、发言、决议、审计。当前在"决议"，六列，四条记录。

再用 CLI 读同一个表格：

![lark-cli 读同一张表](/posts/larkcli/06-表格结构对照.png)

五个表名一字不差。切到"决议"列字段，给出九个：决议ID、议题ID、结论、依据、主要风险、门禁状态、批准时间、批准人、行动项。网页上因为列宽只显示了前六个。

到这一步我才确认，它读的是表结构本身。

接着我想读具体记录，被拦了：

```
missing_scope: bitable:app:readonly, base:record:retrieve
```

表结构能看，行内容不能看。同一张表，两个权限级。我一开始以为是配置写错了，翻了报错提示才明白，飞书的权限按域申请，我之前只授了读结构那一段。

这一点我留了很久。agent 能碰到什么，取决于你给了什么。

读不了行数据，那就试试写。

我想验证的是：CLI 建的日程，在飞书客户端里到底是什么样。先 dry run，不实际发请求：

```bash
lark-cli calendar +create \
  --summary "lark-cli 测试提醒（可删）" \
  --start "2026-11-18T10:00:00+08:00" \
  --end "2026-11-18T10:15:00+08:00" \
  --dry-run
```

返回里能看到它打算发的请求：POST /open-apis/calendar/v4/calendars/<primary>/events。有个细节我没传参，reminders 默认给了 `[{minutes: 5}]`，提前五分钟。

去掉 --dry-run 真建，返回一个 event_id。我切到飞书日历：

![飞书日历](/posts/larkcli/08-飞书日历验证.png)

11 月 18 日 10:00 那一格，蓝色块。

点开看：

![日程详情](/posts/larkcli/09-日程详情.png)

标题、10:00 到 10:15、描述、提前五分钟、组织者，跟我传的参数一致。这条日程在客户端里跟手动建的长得一样，看不出区别。

删的时候第一次没加 --yes，被挡下来：

```
calendar +delete requires confirmation
```

加 --yes 才删掉。之后查 11 月 18 日，日程列表是空的。

高危写操作有这道闸，agent 也绕不过去。对自动化来说是个限制，但我更愿意它存在。

它到底能碰多少东西，我列了一下域：

![23 个业务域](/posts/larkcli/02-覆盖域.png)

二十三个：日历、消息、云文档、多维表格、电子表格、任务、邮箱、会议、审批、考勤、OKR、知识库、白板、妙记、事件订阅。日常在飞书里点的，基本都有。

命令分三层。加号开头的是快捷命令，带默认值，输出是给人看的表；中间一层是跟平台 API 对齐的定型命令；最下面是 `lark-cli api GET /open-apis/...`，直接打原始接口。我上面读表用的就是最下层，因为"列出表"这个动作没有对应的快捷命令。

参数不确定的时候，`lark-cli schema` 能把参数、类型、需要的权限打出来。

技能包是另外一包东西：

![28 个内置技能](/posts/larkcli/04-内置技能.png)

二十八个，编在二进制里，跟 CLI 版本绑死。我理解这是为了避免文档和命令对不上。格式是通用的 SKILL.md，Claude Code、Cursor、Codex 都能直接读，装法是 `npx skills add larksuite/cli -y -g`。

安装我没走一遍，机器上是现成的。流程大概是这样：

```bash
npm install -g @larksuite/cli
npx skills add larksuite/cli -y -g
lark-cli config init
lark-cli auth login
lark-cli auth status
```

config init 会给一个链接，在浏览器里建应用、拿 App ID；auth login 再给一个链接做授权。源码装需要 Go 1.23+ 和 Python 3。

CLI 和技能包要一起装。只装 CLI，agent 不知道每个域怎么用；只装技能包，它没有手。

除了多维表格，我也试了日历和任务：

![真实调用](/posts/larkcli/03-真实调用.png)

calendar +agenda 当天是空的；task +get-related-tasks 返回十六条，我打出前两条。

输出形状固定：ok、identity、data。不用解析表格，不用猜字段。要过滤加 --jq，要演练加 --dry-run。

有人问这跟 MCP 有什么不一样。我的理解是：MCP 要一个 server 常驻，agent 建立连接调；CLI 是个进程，跑完就退。省了维护连接，代价是每次冷启动，没有会话状态，跨步骤的上下文得自己带。

OpenClaw 那边我没试，本机没装。按官方文档的说法，不用碰终端：把仓库链接丢给聊天机器人，让它照手册装，它会跑 npm install、装技能包，然后给你配置链接，授权完就接上。同一套飞书数据，可以同时在 Claude Code 和 OpenClaw 里管。这段只是转述文档。

至于用在哪，我能想到两个比较实在的。

一个是我这种每天到工位先看邮件的人。几十封混着通知、审批、客户消息，让它按优先级分一下，重要的推到项目群，其余归档。

另一个是开完会。妙记里有"下周三前给方案""找小王确认预算"这种句子，让它拆成任务、指派、设截止时间。以前靠人抄，经常漏。

再往下就是配定时任务放后台跑，这类我做得少，不好多说。

云文档、多维表格、日历那几张图都是我自己账号里的，命令输出是这台机器上的真实返回。
